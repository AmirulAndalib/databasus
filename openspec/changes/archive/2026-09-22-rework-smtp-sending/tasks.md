## 1. Shared SMTP transport

- [x] 1.1 Create `backend/internal/util/smtp_transport` with the `Security` enum (`tls`, `starttls`, `none`) in `enums.go`, sentinel errors in `errors.go`, the `Connection` and `Message` types, and `Send(ctx, Connection, Message)`, which opens the connection in the chosen mode and greets with the configured name in every mode. Verify with tests against in-process fake SMTP servers: `tls` delivers, `starttls` upgrades before any other command, `starttls` against a server that does not offer the upgrade fails with `ErrStartTLSNotOffered` and closes the socket having sent nothing past EHLO, not even `QUIT`, `none` never upgrades, and an untrusted certificate fails unless verification is switched off.
- [x] 1.2 Implement PLAIN and LOGIN authentication inside the package. Choose the mechanism from the server's `AUTH` offer (PLAIN first, then LOGIN), refuse either one on an unencrypted connection unless the mode is `none`, match LOGIN prompts from both current prompt sets without regard to case, and fail on any other prompt. Verify with fake-server tests: a stripped STARTTLS offer never produces an `AUTH` command, PLAIN is used when both are offered, LOGIN is used when only it is offered, an unknown prompt ends the attempt, and an authentication error carries the server's response but not the password.
- [x] 1.3 Build messages from parsed addresses: `From` and `To` through `net/mail.Address`, the subject with CR, LF and NUL removed and then Q-encoded, `Message-ID` on the sender's domain, `MIME-Version: 1.0`, `Content-Type: text/html; charset="UTF-8"` and a quoted-printable body. Verify with tests that read the message a fake server received: a subject containing `\r\nBcc: attacker@example.com` produces no `Bcc` header and a single recipient, a non-ASCII display name decodes back to the original, a 5,000-character body line arrives unchanged after decoding with no wire line over 998 characters, and two messages carry different `Message-ID` values.
- [x] 1.4 Bound the whole conversation with a 30-second deadline derived from the caller's context and applied to both the dial and the connection. Verify with a test against a server that greets and then goes silent, using a shorter caller deadline so the test runs quickly, and assert that `Send` returns a timeout error within that deadline.
- [x] 1.5 Add `GetDefaultSecurityForPort`, `ParseSender` (a bare address or a display name with an address, with `Databasus` as the default name), `ResolveSender(from, username, host)` (the explicit sender, else the username only if it parses as a bare address, else `noreply@` and the host), `ValidateHeloName` (a host name or an address literal) and `GetDefaultHeloName(databasusURL)` (the host part only, then the machine host name, then `localhost`; an IPv4 address as `[192.0.2.1]`, an IPv6 address as `[IPv6:2001:db8::1]`). Verify with table tests for each function, including a URL with a port, an IPv4 and an IPv6 host, a sender such as `ops at example`, which must be rejected, a username `apikey` resolving to `noreply@<host>`, and greeting names `my relay` and `[::1]`, which must be rejected.
- [x] 1.6 Run `make lint` and `go test ./internal/util/smtp_transport/... -count=1`.
